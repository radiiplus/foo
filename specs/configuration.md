# Configuration Source

Version: 1.

FOO projects use `project.ivc`. The configuration grammar is independent of
FOO source code and can configure other applications through named capabilities.
An authored `.ivc` contains configuration values and capability selections.
An authored `.cap` declares one capability's schema; project-owned capability
definitions MUST use the `.cap/NAME.cap` path. Generated copies live under
`.artifacts/.cap/`.

The compiler reads configuration through a dedicated parser before the build
planner, package resolver, or QBE backend runs. The source format is UTF-8 and
is versioned internally as format 1; authors do not declare `format`.
Each `capability "NAME"` declaration selects one named schema;
several may be selected in the same configuration. Declarations are
`name is value`, `name enable`,
`name disable`, `name using implementation`, or `name { declarations }`.
`name "instance" { declarations }` creates a named child of a section.
Names contain ASCII letters, digits, underscores, and hyphens and begin with
a letter. Strings use JSON-compatible double-quoted escapes. Values include
strings, signed 64-bit integers, finite floats, booleans, null, lists, and
nested sections. Lists use commas. `#`, `//`, and `--` start line comments.

`import "relative/path.ivc"` imports within the root configuration
directory. Imports are processed in source order. Objects merge recursively.
A declaration in an importing file replaces a value from an imported file;
later section blocks also replace earlier blocks. Duplicate values within one
block are errors. `override name is value` can
explicitly replace an existing value, including a whole object. Package
commands append declarations to imported manifests without flattening them.
Import cycles, escaping paths, duplicate declarations in one file, and authored
`format` fields are errors with source positions. Files are limited to 1 MiB, import
graphs to 64 files, and nesting to 32 levels.

Decimal size suffixes `KB`, `MB`, `GB`, `TB` use powers of 1000. Binary
suffixes `KiB`, `MiB`, `GiB`, `TiB` use powers of 1024. Durations `ms`, `s`,
`min`, and `h` normalize to nanoseconds. Overflow is an error. Quantities are
stored as signed 64-bit canonical integers and must be validated against the
field type supplied by a capability before use.

The project capability defines the existing manifest fields and their types.
`capability "project"` explicitly activates it. Other capabilities are
project-local and require a versioned declarative definition. Selected
capabilities are materialized automatically as `.artifacts/.cap/NAME.cap`;
the built-in project definition becomes `.artifacts/.cap/project.cap`.
Config checks, emission, and project builds regenerate these files from their
source after deletion or edits. Emitted images belong under `.artifacts/config/`;
`foo.ivl` is the JSON dependency lockfile, generated by package commands and
colored by the editor extension. Field IDs and image bytes are
versioned separately from this source grammar. The image module emits
deterministic bytes only; image decoding and runtime loading are not supported.
`foo config check` validates the manifest and selected capabilities.
`foo config emit` writes `.artifacts/config/config.cimg` without loading it.

## Capability Definitions

An explicit `capability "network"` declaration selects the project-owned
`.cap/network.cap` source, validates it, and generates
`.artifacts/.cap/network.cap`. Selection never scans
arbitrary dependency directories. The definition uses the same declaration grammar:

```cap
namespace is "network"
version is 1
fields {
  port {
    type is "integer"
    required enable
    min is 1
    max is 65535
  }
  endpoint {
    type is "string"
    default is "127.0.0.1"
    aliases is ["host"]
  }
}
```

Selected namespaces may occur in any `.ivc` source, including standalone
configuration such as `service.ivc`. For example, select
`capability "network"` and declare `network { port is 8080 }`. Define
`.cap/network.cap` beside that source. `foo config check service.ivc`
validates it, and `foo config emit service.ivc` writes
`.artifacts/config/service.cimg` beside it. Unclaimed top-level fields are
errors. The project manifest is one specific use of the same capability
system. Supported types are string, integer, size,
duration, float, boolean, list, and object. Numeric fields may have `min` and
`max`; `allowed` is a nonempty list of permitted values. Aliases, defaults,
required fields, unknown fields, duplicate definitions, and dependency cycles
are checked. `requires is ["other"]` demands an explicit selection of the
named capability. Only schema version 1 is accepted. Capability files are
declarative and cannot import configuration files or execute code.
The VS Code extension colors `.ivc`, `.cap`, and `.ivl` files.

The project capability is defined in `src/config/project.cap` and materialized
under `.artifacts/.cap/project.cap`. Other namespaces are independently
validated. Their source and `.cap` bytes participate in the build fingerprint.

## Image Emission

Emission produces a portable little-endian image with magic `FCOI`, byte
version 1, a 32-byte schema digest, a 32-byte payload checksum, a 32-bit field
count, sorted field entries, and a typed value region. Field entries contain a
16-bit name length, name bytes, a 64-bit stable field ID, a one-byte type tag,
and 32-bit offset and length. Values encode null, boolean, signed 64-bit
integer, IEEE 754 double, string, list, and sorted record. Field IDs are the
low 64 bits of SHA-256 over `foo.config.field/v1` followed by a zero byte and
the field name. The schema digest incorporates the project schema version and
the selected capability file hashes. Images are limited to 16 MiB, 65,535
fields per record, and 32 nesting levels. This version has no decoder or
runtime image access API.

The first integration stage replaces generated project manifests and all
native manifest readers. Declared script execution for producing capability
sources, static FOO value binding, and dynamic loading are subsequent validated
stages. No
performance comparison is implied by this specification.
